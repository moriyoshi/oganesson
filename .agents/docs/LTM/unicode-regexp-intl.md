# Internationalization and Unicode/RegExp Handling

## Summary

Oganesson provides the web platform's `Intl` object via FormatJS polyfills
(no Node, no native ICU) and reconciles ECMAScript's Unicode-aware RegExp
features with Sobek's regexp engine. Sobek now handles `\p{...}` property
escapes natively, so only the `v` flag's set notation and its properties of
strings (emoji sequences) are emulated in the prelude on top of Go-generated
tables.

## Key Facts

- `Intl` comes from FormatJS polyfills, vendored exact-pinned by the
  `formatjs` function in `scripts/vendor-js.sh`; there is no Go-side Intl
  implementation (`runtime/webapi/intl.go` and the old rivo/uniseg segmenter
  are gone).
- Lazy groups: `getCanonicalLocales` / `Locale` / `Segmenter`, plus
  `PluralRules` / `NumberFormat` / `DateTimeFormat` (and `ListFormat`,
  `RelativeTimeFormat`, `DisplayNames`) are installed as accessors in
  `runtime/webapi/js/src/intl.ts`; first access swaps in the real polyfill so
  request VMs that never use Intl never load locale data.
- `DateTimeFormat` uses English data, every time zone, default zone from `TZ`.
- `Collator` is backed by `golang.org/x/text/collate` (not FormatJS).
- Sobek handles `\p{...}` / `\P{...}` property escapes natively; the old
  property-escape rewriter (prelude shim + Go rewriter + generated tables) was
  deleted (2026-10-08).
- The `v` flag is emulated: `runtime/webapi/js/src/unicodesets.ts` translates a
  `v` pattern into an equivalent `u` pattern; properties of strings (emoji
  sequence sets) come from `emoji_tables.go`, generated by
  `runtime/webapi/internal/genemoji`.
- Tests: `TestRegExpUnicodeSets`, `TestRegExpPropertiesOfStrings`.

See [[js-language-gaps-and-lowering]] for how regex literals are lowered to
`new RegExp(...)` so the prelude shims can intercept them.

## Details

### Intl from FormatJS

At the user's direction (per the reuse-prior-work rule), FormatJS's polyfills
replaced any hand-written Intl support. `scripts/vendor-js.sh` (the `formatjs`
function) vendors the exact dependency closure (all MIT):

| Package | Version |
| --- | --- |
| `@formatjs/fast-memoize` | 3.1.7 |
| `@formatjs/intl-getcanonicallocales` | 3.2.12 |
| `@formatjs/intl-supportedvaluesof` | 2.3.11 |
| `@formatjs/intl-locale` | 5.3.12 |
| `@formatjs/intl-localematcher` | 0.9.0 |
| `@formatjs/intl-segmenter` | 12.2.15 |

They live in `runtime/webapi/js/vendor/node_modules/@formatjs/` so their bare
imports of one another resolve when genprelude bundles. `.gitignore` needs
`!/runtime/webapi/js/vendor/node_modules/`, since the root `node_modules/` rule
would otherwise silently drop them.

**Lazy loading.** `js/src/intl.ts` creates `Intl` and defines each formatter
group (`getCanonicalLocales`, `Locale`, `Segmenter`, and the formatter groups
`PluralRules`, `NumberFormat`, `DateTimeFormat`, `ListFormat`,
`RelativeTimeFormat`, `DisplayNames`) as accessors. The first access deletes
the accessor and `require()`s the relevant `polyfill-force.js` module(s);
esbuild evaluates ESM at its `require()`, not at prelude start, so request VMs
that never touch Intl never run FormatJS's locale data. Order matters:
segmentation's default "best fit" locale matching calls
`new Intl.Locale(...).maximize()`. `DateTimeFormat` ships English data for
every time zone and reads the default zone from the `TZ` env var (Astro's
logger formats times, which is what forced these groups in).

`Collator` is provided separately via `golang.org/x/text/collate`.

### RegExp Unicode property escapes (historical, now native)

Goja's regexp transpiler (`parser/regexp.go`, `scanEscape`) had no case for
`p` / `P`, so `/\p{L}/u` compiled to `/p{L}/` and matched only the literal
text `p{L}`. This broke FormatJS's `isWordLike` (`/[\p{L}\p{N}\p{M}]/u`) and
satori's language detection (`\p{scx=Han}`, etc.). A prelude shim
(`js/src/regexp.ts`) plus a Go rewriter (`runtime/webapi/regexp.go`,
`regexpRewrite`) plus generated `unicode_tables.go` (from
`internal/genunicode`) rewrote each escape into `\u{…}` ranges using Go's
`unicode` package and the UCD.

After the switch to Sobek, which handles property escapes natively, that whole
half was deleted (2026-10-08, with user approval): `runtime/webapi/regexp.go`,
`runtime/webapi/unicode_tables.go`, `runtime/webapi/internal/genunicode/`, and
`ogapi.RegExpLiterals` (`_tsoverlay/ogapi/module.go`). The removed span type's
role is now served by `Span`, still used by `ClassFieldNames` and
`ImportMetaURLs`; the facade was re-installed into `third_party/typescript`.

### The v flag's set notation

Sobek has neither the `v` flag nor its set notation; the prelude's RegExp ran
`v` patterns as `u` only when they meant the same.
`runtime/webapi/js/src/unicodesets.ts` translates a `v` pattern into an
equivalent `u` pattern:

- Outside classes the pattern is copied; each class becomes an atom.
- A class of single code points stays a `u` class (`[a-z\p{L}]`), nested plain
  classes spliced in; otherwise an alternation of one-code-point atoms.
- `A&&B` is `(?:(?=B)A)`, `A--B` is `(?:(?!B)A)` (both match exactly one code
  point at the same place, so the lookaround is exact); a negated class
  without strings is `[^…]` or `(?:(?!X)[\s\S])`.
- `\q{…}` strings are alternatives, longest first, then single code points,
  then the empty string (the spec's order); `&&` / `--` on strings act on the
  literal sets.
- v-mode syntax checks reproduce V8's SyntaxErrors: unescaped
  `( ) [ ] { } / - \ |`, reserved double punctuators, mixed operators,
  out-of-order ranges, a negated class that may contain strings.
- Characters are emitted as `\u{…}`, so v-mode escapes (`\&`, `\-`, `\!`) need
  no u-mode equivalent.
- A translated RegExp keeps the written pattern as its own `source`
  (`toString`, `new RegExp(re)` read it).

### The v flag's properties of strings (emoji sequences)

ECMAScript's properties of strings are exactly the emoji sequence sets:
`Basic_Emoji`, `Emoji_Keycap_Sequence`, `RGI_Emoji_Flag_Sequence`,
`RGI_Emoji_Modifier_Sequence`, `RGI_Emoji_Tag_Sequence`,
`RGI_Emoji_ZWJ_Sequence`, and their union `RGI_Emoji`. The per-code-point
properties are Sobek's own. Neither Go's `unicode` (17.0.0) nor
`golang.org/x/text` has emoji sequence data, so it is generated from Unicode's
files.

- `runtime/webapi/internal/genemoji` (`go generate`; downloads Unicode
  17.0.0's `emoji-sequences.txt` and `emoji-zwj-sequences.txt`, and the
  Unicode License) writes `emoji_tables.go` (single code points as ranges,
  longer strings) and `emoji_tables.LICENSE`, which `scripts/collect-notices.sh`
  includes.
- `emoji.go`: the host's `stringProperty(name)` returns `{ content, strings }`
  (a u-mode class body, cached per property, plus the strings).
- In `unicodesets.ts`, `\p{…}` of a property of strings becomes that set, both
  inside classes (set operations on strings act on the literal sets) and
  outside them (as the class of it); `\P{…}` of one, and negated classes
  containing one, are SyntaxErrors, as in Node.

(An earlier attempt vendored Babel's regenerate-unicode-properties in JS; the
user asked for the table on the Go side instead, so that was removed.)

## Files

- `runtime/webapi/js/src/intl.ts` ... creates `Intl`, installs each formatter
  group as a lazy accessor over FormatJS polyfills.
- `runtime/webapi/js/vendor/node_modules/@formatjs/` ... vendored FormatJS
  packages.
- `scripts/vendor-js.sh` (`formatjs` function) ... vendors the exact FormatJS
  dependency closure.
- `runtime/webapi/js/src/unicodesets.ts` ... translates `v`-flag patterns
  (set notation, `\q{…}` strings, properties of strings) into `u` patterns.
- `runtime/webapi/emoji.go` ... host `stringProperty(name)` serving emoji
  sequence sets to the prelude.
- `runtime/webapi/emoji_tables.go` ... generated emoji sequence tables.
- `runtime/webapi/internal/genemoji` ... `go generate` tool that downloads
  Unicode 17.0.0 emoji files and writes `emoji_tables.go` + its LICENSE.

Deleted after the Sobek switch (do not look for them): `runtime/webapi/intl.go`,
`runtime/webapi/regexp.go`, `runtime/webapi/unicode_tables.go`,
`runtime/webapi/internal/genunicode/`, `js/src/regexp.ts`.

## Test Coverage

- `TestRegExpUnicodeSets` ... 21 patterns against Node 24's matches and errors,
  literals (esbuild lowers `v` literals to the constructor), and
  `source` / `toString` / `flags` / `new RegExp(re)`. Neutralized by dropping a
  subtraction's lookahead (matches differ) or the own-`source` behavior.
- `TestRegExpPropertiesOfStrings` ... each property, ZWJ / flag / keycap /
  modifier / tag sequences, a subtraction, matching inside a longer string, and
  the two error cases, all against Node 24. Neutralized by not installing the
  `stringProperty` host function.
- `TestIntlSegmenter` runs on FormatJS (`isWordLike` included).

## Pitfalls

- `genemoji` and FormatJS vendoring need network access; `go generate` for the
  emoji tables downloads from Unicode and checks the UCD version.
- Emoji tables must track Sobek's / the UCD's Unicode version (17.0.0);
  per-code-point properties come from Sobek, only sequence sets are generated.
- Properties of strings only exist under the `v` flag; using `\P{…}` of one, or
  putting one in a negated class, is a SyntaxError (matching Node) because the
  set contains multi-code-point strings.
